# Amiri — трекер расходов в Telegram · веб-панель

Расходы по категориям и дням, правка, лимиты и выгрузка. Вход — через бота,
без регистрации и пароля.

**Бот:** [@amiri_expenses_bot](https://t.me/amiri_expenses_bot)
**Панель:** _(добавится после деплоя)_
**Бот и API:** [`../backend`](../backend) — отдельное приложение в этом же репозитории

Здесь — только панель. Данные приходят из API — он лежит рядом,
в [`../backend`](../backend).

---

## Что на экране

- **Обзор** — итог за период и сравнение с прошлым, круговая по категориям,
  столбцы по дням, быстрый ввод «кофе 350», последние расходы
- **Расходы** — список с фильтром по датам и категории, сумма по фильтру,
  выгрузка CSV
- **Настройки** — язык, основная валюта, лимиты на месяц с прогрессом,
  свои категории, срок сессии

Период задаётся тремя пресетами или двумя датами — графики и суммы
перестраиваются под него.

- Node 20+

## Запуск

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

Панель: http://localhost:5173

Порт 5173 важен: он прописан в `PANEL_URL` бэкенда — оттуда берётся адрес
для ссылки входа и для CORS.

**Сборка**

```bash
npm run build     # dist/
npm run preview   # проверить сборку локально
```

## Переменные окружения

Шаблон — `.env.example`. Все переменные Vite должны начинаться с `VITE_`.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `VITE_BOT_USERNAME` | `amiri_expenses_bot` | Кнопка «Открыть бота» на странице входа |
| `VITE_API_URL` | пусто | Адрес API. Пусто — запросы идут на `/api` того же домена |
| `VITE_API_TARGET` | `http://127.0.0.1:8000` | Куда Vite проксирует `/api` при разработке |

На проде вариантов два: положить панель и API за один домен и оставить
`VITE_API_URL` пустым, либо вписать туда полный адрес API — тогда бэкенд
должен разрешить этот origin в CORS.

## Как устроено

```
src/
├─ main.tsx              # роутер + провайдер сессии
├─ App.tsx               # три состояния: загрузка, гость, вход выполнен
├─ pages/
│  ├─ Login.tsx          # три шага входа + кнопка бота
│  ├─ AuthPage.tsx       # /auth?token=… — обмен ссылки на сессию
│  ├─ Dashboard.tsx      # итог, категории, дни, последние расходы
│  ├─ ExpensesPage.tsx   # список с фильтрами и выгрузкой
│  └─ SettingsPage.tsx   # язык, валюта, лимиты, категории, сессия
├─ components/
│  ├─ charts.tsx         # круговая и столбцы (Recharts)
│  ├─ ExpenseList.tsx    # список + диалог правки
│  ├─ QuickAdd.tsx       # строка «кофе 350»
│  ├─ SuggestionCard.tsx # ответ на предложенную AI категорию
│  ├─ LimitsCard.tsx     # лимиты с прогрессом
│  ├─ DateRange.tsx      # период: пресеты и две даты
│  ├─ CategoryIcon.tsx   # цветной квадрат категории с иконкой
│  ├─ Layout.tsx         # сайдбар на компьютере, нижняя навигация на телефоне
│  └─ ui.tsx             # Card, Button, Tabs, Skeleton
├─ hooks/
│  └─ useAuth.tsx        # состояние сессии: загрузка · гость · вход выполнен
└─ lib/
   ├─ api.ts             # клиент, сессия, скачивание CSV
   ├─ types.ts           # типы ответов API
   ├─ format.ts          # деньги, даты
   ├─ icons.ts           # категория → иконка lucide
   └─ telegram.ts        # Mini App
```

**Вход — два пути, одна сессия.** Ссылка из `/panel` меняется на сессию
(`/auth?token=…`), либо панель открывается внутри Telegram и сама
авторизуется через `initData`.

Основной способ хранения сессии — httpOnly-cookie: JavaScript до неё не
дотягивается. Но часть браузеров не сохраняет cookie для localhost, поэтому
тот же токен дублируется в `localStorage` и уходит заголовком
`Authorization`. Любой `401` чистит сессию и возвращает на страницу входа —
вместо бесконечного спиннера.

**Скачивание CSV идёт через `fetch`, а не ссылкой.** Обычная навигация не
отправляет заголовок `Authorization` — файл приходил бы с `401`.

**Иконки — lucide, не эмодзи.** Категории с бэкенда приходят с эмодзи (они
нужны боту), но в панели каждая категория рисуется иконкой из
`lib/icons.ts`; свои категории получают `Tag`.

**Цвет категории — один на весь интерфейс.** Он приходит с бэкенда и
используется в круговой диаграмме, в списке и в лимитах, чтобы категорию
можно было узнать не читая.

**Тема следует настройке системы.** Палитра — CSS-переменные в `index.css`,
подставляются в Tailwind через `@theme inline`.

**Адаптивность.** Сайдбар от 1024px, ниже — нижняя навигация. Карточкам
задан `min-w-0`: без этого Recharts не даёт колонке сжиматься и страница
уезжает вбок при сужении окна.

## Деплой

Панель собирается в Node и раздаётся nginx. Тот же nginx проксирует `/api` и
`/webhook/` на контейнер API — панель и бэкенд оказываются на одном origin,
поэтому cookie сессии работает без оговорок, CORS не нужен, и на весь проект
хватает одного домена.

Разворачивается вместе с бэкендом, одной командой из корня репозитория:

```bash
bash deploy/setup.sh
nano .env
docker compose up -d --build
```

Панель поднимется на порту **8348** — нестандартном, чтобы не столкнуться с
тем, что уже занято на сервере. Меняется через `WEB_PORT` в `.env`.

Полное описание — в [README репозитория](../README.md#деплой-одной-командой).

### Если API на отдельном домене

По умолчанию панель шлёт запросы на свой же origin. Если API вынесен на
другой домен, при сборке:

```bash
PANEL_API_URL=https://api.вашдомен docker compose up -d --build
```

Тогда бэкенду нужно разрешить этот origin: `PANEL_URL` в его `.env`.

> Переменные сборки называются `PANEL_*`, а не `VITE_*`, намеренно: compose
> читает `.env` из корня, и локальное значение `VITE_API_URL` случайно
> попало бы в продовый образ.
